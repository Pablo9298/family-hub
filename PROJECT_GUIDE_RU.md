# Карта Family Hub — пояснения к проекту

Этот документ дополняет комментарии внутри исходных файлов. Он объясняет **кто за что отвечает** и **как передаются данные**. Не нужно читать всё подряд: начинай с потока ниже.

## Общий путь данных

```text
HTML страница -> JS события -> api.js -> HTTP с cookie -> Express
       ↑                                             ↓
 JS перерисовывает страницу <- JSON ответ <- PostgreSQL
```

**Транзакция:** нажали «Добавить» (`dashboard.html`) → `main.js` прочитал поля → `api.js` отправил `POST /workspaces/:id/transactions` → `workspaceTransactions.js` проверил права и записал PostgreSQL → `transactions.js` загрузил новый список и обновил баланс/историю.

**Аналитика:** `analytics.html` подключает `analyticsPage.js` → проверка Google-сессии через `/auth/me` → список доступных пространств `/workspaces` → выбор пространства → `GET /workspaces/:id/transactions` → `analytics.js` считает суммы и строит графики. На странице аналитики **нет** добавления/редактирования транзакций.

**Переключение страниц:** обе страницы используют `workspaceSelection.js`. Этот модуль хранит предпочтение через `sessionStorage` с отдельным ключом для текущего Google-пользователя; он **не заменяет** авторизацию. Каждый раз клиент сначала проверяет список разрешённых пространств с сервера.

## frontend/

| Файл | Зачем нужен |
|---|---|
| `index.html`, `landing.css` | Страница входа/презентации до авторизации, её оформление. |
| `dashboard.html` | Основной интерфейс: суммы, история, создание/изменение/удаление, пространство и участники. Графики сюда больше не встроены. |
| `analytics.html` | Отдельная страница отчётов с фильтром периода и выбором вида графиков. |
| `style.css` | Две цветовые темы, общие компоненты, модальные окна, диаграммы, нижняя навигация. |
| `script.js` | **Старый неиспользуемый прототип** до workspaces; не подключать к актуальной странице. |

### frontend/js/

| Файл | Зачем нужен |
|---|---|
| `main.js` | Точка входа Dashboard: авторизация, события форм, смена пространства, запуск модулей. |
| `analyticsPage.js` | Точка входа Analytics: авторизация, выбор пространства, период, загрузка и отрисовка отчётов. |
| `analytics.js` | Чистые расчёты по категориям/месяцам и функции создания SVG/CSS-диаграмм в DOM. |
| `transactions.js` | Список транзакций выбранного пространства, баланс, история, защита от устаревших ответов. |
| `api.js` | Функции HTTP-запросов к Express, передача cookie, проверка ошибок, текущий workspace **только в памяти страницы**. |
| `workspaceSelection.js` | Запоминание выбранного workspace при переходе между страницами с проверкой доступа. |
| `filters.js` | Даты, периоды и фильтр истории на Dashboard (без запросов к БД). |
| `categories.js` | Подсказки категорий и обновление при смене типа операции/пространства. |
| `invitations.js` | Меню аккаунта, приглашения, принятие/отклонение. |
| `workspaceMembers.js` | Просмотр участников, приглашение по email, удаление участника владельцем. |
| `ui.js` | Общие функции: поиск элемента по ID, формат денег, экранирование HTML, toast, темы. |

## backend/

| Файл | Зачем нужен |
|---|---|
| `server.js` | Создаёт Express, подключает CORS, сессии, маршруты, содержит **заблокированные старые** API-обработчики. |
| `db.js` | Пул `pg`, выбор `.env.development`/`.env`, запрет неправильной БД для режима. |
| `session.js` | Серверные сессии PostgreSQL, cookie и настройки безопасности. |
| `auth.js` | Маршруты Google OAuth, проверка ответа Google, вход/выход. |
| `googleAuth.js` | Конфигурация OpenID Connect клиента Google. |
| `authUsers.js` | Связь Google-профиля с локальной записью пользователя. |
| `workspaces.js` | Создание/список пространств, участники, приглашение, удаление участников. |
| `workspaceTransactions.js` | Доступ к операциям внутри workspaces; CRUD и контроль membership. |
| `categories.js` | Нормализация и создание категории в конкретном workspace. |
| `invitations.js` | Список приглашений пользователя, принятие и отклонение. |
| `test-db.js` | Ручная проверка соединения с PostgreSQL; не автоматический тест. |
| `data.json` | Старое локальное хранилище до PostgreSQL; не используется в актуальном API. |

### backend/middleware/

- `requireAuth.js` — сессия обязана содержать авторизованного пользователя.
- `requireWorkspace.js` — пользователь должен состоять в выбранном пространстве.
- `requireWorkspaceOwner.js` — отдельные действия разрешены только создателю пространства.
- `requireTrustedOrigin.js` — промежуточная проверка `Origin` для локального интерфейса; **не полноценная production-CSRF-защита**.

### SQL и конфигурация

- `migrations/001_*.sql`, `002_*.sql`, `003_*.sql` — последовательная история изменений схемы PostgreSQL; не применять повторно вслепую.
- `seeds/dev_transactions.sql` — тестовые данные только для `family_hub_dev`; **не запускать на реальной базе**.
- `sql/` — исторические учебные запросы, включая изменяющие/удаляющие; **не использовать как миграции**.
- `compose.yml` — запускает PostgreSQL в Docker с постоянным volume, но **не** backend/frontend.
- `backend/package.json`, `package-lock.json` — библиотеки и команды npm. Формат JSON не допускает комментариев; пояснения находятся здесь.
- `.gitignore` — исключает секреты, зависимости, дампы и логи из Git.

## Что читать первым

1. `frontend/dashboard.html` — имена и ID элементов.
2. `frontend/js/main.js` — обработчики пользовательских действий.
3. `frontend/js/api.js` — какой HTTP запрос отправляется.
4. `backend/workspaceTransactions.js` — как проверяются права и отправляется SQL.
5. `frontend/js/transactions.js` — почему после записи обновляется история.
6. `frontend/analytics.html`, `frontend/js/analyticsPage.js`, `frontend/js/analytics.js` — новая отдельная страница и графики.

## На что обращать внимание при изучении

- `id` в HTML связывает поле с JavaScript: его переименование без изменения JS приводит к ошибке.
- `type=module` означает независимые JS-модули с `import/export`.
- `sessionStorage` — удобство интерфейса, но не механизм разрешений.
- `credentials: 'include'` передаёт cookie с серверной сессией.
- `requireWorkspace` на сервере обязателен даже если UI не показывает чужие пространства.
- SQL `BEGIN/COMMIT` нужен для атомарных изменений, когда действий несколько.
- Смена workspace очищает старый список до загрузки новых данных.
