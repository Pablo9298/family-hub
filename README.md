# Family Hub — семейный финансовый помощник

Это учебный проект с рабочим прототипом: **Node.js / Express + PostgreSQL + Google OAuth + HTML/CSS/JS**. Новые страницы разделены: `frontend/dashboard.html` и `frontend/analytics.html`.

> **Важно.** Это не готовый публичный SaaS. Не публикуй Express/базу через открытые порты до аудита безопасности, HTTPS, настройки Google OAuth, CSRF-защиты и резервных копий.

## Что сейчас реализовано

- Вход через Google, серверные сессии в PostgreSQL.
- Финансовые пространства и участники; приглашения с принятием/отклонением.
- Доходы/расходы: добавление, редактирование, удаление, история и фильтры.
- Баланс на Dashboard.
- Отдельная страница «Аналитика»: кольцевая диаграмма категорий и сравнение последних 6 месяцев; выбор типа отчёта и периода расходов.
- Светлая/тёмная тема, сохранение выбранного пространства между страницами **в одной вкладке**.

## Запуск в уже настроенной локальной среде

В оригинальном проекте файлы `.env` и `.env.development` содержатся **только на твоём компьютере**: в архив их специально не включали.

1. Подними локальный PostgreSQL через `sudo docker compose up -d` из корня (если Compose и локальный `.env` уже настроены).
2. Проверь, что тестовая БД `family_hub_dev` существует и на неё уже применены миграции. **Не запускай миграции повторно вслепую**: часть из них предназначена для одноразового применения.
3. В `backend/`: `npm ci`, затем `npm run dev`. Требуется `.env.development` с параметрами соединения, сессии и Google OAuth.
4. Из корня проекта запусти `python3 -m http.server 5500` и открой `http://localhost:5500/frontend/index.html`.
5. После Google-входа Dashboard: `http://localhost:5500/frontend/dashboard.html`, Аналитика: `http://localhost:5500/frontend/analytics.html`.

Нынешний frontend и backend **жёстко настроены на localhost и эти порты**. С телефона другого устройства `localhost` указывает на сам телефон; такой запуск не предназначен для сетевого доступа с телефона жены.

## Как безопасно вносить обновление

- Сохрани резервную копию собственного репозитория и базы до копирования новой версии.
- Применяй изменения к отдельной ветке от `develop`, проверь `git diff`, а затем тестируй.
- Не копируй старые дампы/реальные финансовые данные из архива.
- Не выполняй `backend/sql/*.sql` на рабочей базе.
- Не переноси код в `main`, пока не пройдены проверки из чек-листа.
