# Проверка готовности Family Hub для семьи

**Состояние по исходному коду ZIP (ноябрь 2026).** Это статическая проверка кода и структуры; у нас нет доступа к живому Google OAuth, реальному Docker/PostgreSQL и двум твоим устройствам. Поэтому «готово» означает, что реализация существует в коде, а не то, что все сценарии доказанно прошли на вашем оборудовании.

## Что видно в проекте

- Есть Google OAuth и серверные сессии в PostgreSQL.
- CRUD транзакций внутри workspaces, категории, исторические фильтры, расчёт баланса.
- Есть приглашения/участники; право владельца проверяется на сервере.
- Есть аналитика расходов и месячный график (теперь отдельная страница).
- Старые API `/transactions` и `/categories` блокируются через 410, несмотря на оставшийся устаревший код в `server.js`.

## ОБЯЗАТЕЛЬНО до реального семейного использования

1. **Изолировать реальные данные.** Тестовые seed-операции находятся только в `family_hub_dev`. Для настоящих операций нужна отдельная корректно мигрированная база `family_hub`, не копия с тестовыми счетами. Перед запуском проверь `NODE_ENV` и DB_NAME по логам и настройкам.
2. **Настроить резервное копирование.** Docker-volume не заменяет backup. Нужен регулярный `pg_dump` в защищённое место вне этого компьютера, защита файла и хотя бы один проверенный тест восстановления. Не выкладывать дампы в Git и не присылать их вместе с исходным кодом.
3. **Не открывать localhost API в интернет.** В `api.js`, `workspaceMembers.js`, `invitations.js` и `index.html` захардкожены `localhost`/порты; у сервера статичный CORS и Origin, а OAuth редиректит на localhost. С телефона жены другой адрес устройства; простое открытие портов будет и нерабочим, и небезопасным.
4. **Продумать безопасный способ доступа.** В локальной сети можно тестировать на одном ПК. Для второго устройства нужен согласованный URL, защищённый доступ (например, частная сеть), HTTPS/корректные cookie и новая конфигурация Google OAuth. Перед публичным запуском потребуется полноценная CSRF-защита, rate limiting, настройка reverse proxy и безопасность сессий.
5. **Проверить участников на двух реальных Google-аккаунтах.** Приглашение, принятие, добавление операций обоими пользователями, доступность одной истории, удаление участника и запрет дальнейшего доступа.
6. **Проверить финансовые крайние случаи.** Неверные суммы/даты, повторный клик отправки, отсутствие сети после POST, фильтр периода, смена пространств во время запроса. Подозрительные ошибки в `try/catch` могут показывать «не удалось добавить» при успешной записи и сбое обновления списка.

## Желательно перед переносом develop → main

- Убрать/изолировать исторический код `frontend/script.js`, неактивные CRUD-маршруты и учебные SQL-скрипты из релизного пакета (сейчас они оставлены для учебной истории).
- Дописать автоматизированные API/браузерные тесты, в том числе проверку разграничения доступа между workspaces.
- Настроить запуск frontend/backend после перезапуска компьютера и мониторинг ошибок.
- Проверить мобильный экран: диаграммы, подсказки по столбцам, видимость нижней навигации.
- В будущем переводить суммы для расчёта с JS `Number` в целые центы или использовать точную десятичную арифметику.

## Ручной тест после замены кода

1. `node --check` для изменённых JS и старт `npm run dev`.
2. Google-вход, Dashboard, смена workspace, добавление/редактирование/удаление тестовой записи **только в DEV**.
3. Открыть «Аналитика», сравнить суммы с Dashboard при одинаковом периоде; сменить workspace и вернуться на главную.
4. Переключатели «Все графики», «Расходы по категориям», «По месяцам»; пустой период, неверные даты, светлая и тёмная темы.
5. В другом аккаунте проверить, что нельзя видеть чужое пространство даже по вручную введённому URL/API.
6. Только после живого тестирования и настройки backup — отдельное решение о переносе в `main`.

## Что этот ZIP намеренно НЕ содержит

`.env`, `.env.development`, пользовательскую PostgreSQL БД, дампы `family_hub_backup.sql` и `family_hub_before_002.sql`, `backend/data.json`, `.git`, `node_modules`. В исходном загруженном ZIP дампы присутствовали; они исключены из этого обновлённого пакета ради приватности.
